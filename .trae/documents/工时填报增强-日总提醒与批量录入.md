# 工时填报增强：日总不足8h提醒 + 批量录入

## Context

当前工时日报功能（`src/app/(dashboard)/time-entries/page.tsx`）仅支持单条逐次填报，多项目并行时需反复打开对话框。且填报后无日总工时反馈，用户无法感知当日是否填满 8 小时。本次需求：
1. 每日录入工时后，总计不足 8 小时提醒用户
2. 支持多项目并行批量录入工时

## 实现方案

### 一、后端 API 改动

#### 1. 修改 `src/app/api/time-entries/route.ts` — POST 返回日总工时

在 upsert 完成（现有 line 120-155）之后，追加一次查询获取该用户当日的所有工时总和，返回新字段：

```ts
// upsert 后查询当日总工时
const { data: dailyAfter } = await client
  .from('time_entries')
  .select('hours')
  .eq('user_id', currentUser.id)
  .eq('work_date', work_date);
const dailyTotal = (dailyAfter || []).reduce(
  (sum: number, e: { hours: string }) => sum + parseFloat(e.hours), 0
);

return NextResponse.json({
  data: result,
  daily_total: Math.round(dailyTotal * 10) / 10,
  is_below_minimum: dailyTotal < 8,
}, { status: 201 });
```

#### 2. 修改 `src/app/api/time-entries/[id]/route.ts` — PUT 同步返回日总工时

在 update 完成（line 60-65）后，用 `existing.user_id` 和 `existing.work_date` 查询当日总工时，同样返回 `daily_total` 和 `is_below_minimum`。

#### 3. 新建 `src/app/api/time-entries/batch/route.ts` — 批量填报端点

**请求体**：
```ts
{
  work_date: string;             // 共享日期
  coordination_matters?: string; // 共享，可选
  tomorrow_plan: string;         // 共享，必填
  entries: Array<{
    project_id: number;
    hours: string;
    completed_work: string;
    remarks?: string;
  }>;
}
```

**响应**：`{ data: TimeEntry[], daily_total: number, is_below_minimum: boolean }`

**校验流程（先全量校验，再写入）**：
1. 鉴权（复用 `getSessionUser`）
2. `entries` 非空数组，`work_date` 和 `tomorrow_plan` 必填
3. 逐行：`project_id`/`hours`/`completed_work` 必填；hours 为有效数 `0 < x ≤ 8` 且 0.5 倍数
4. 批量内 `project_id` 去重（不允许同项目出现两次）
5. 查询当日已有工时 + 批量总和 ≤ 8（考虑 upsert 场景需扣除被替换的旧值）
6. 非 admin 校验每个项目的成员关系
7. 逐项目校验预估工时上限

**写入**：逐行 upsert（同 user+project+date → update），完成后查当日总工时返回。

### 二、前端改动

#### 4. 新建 `src/app/(dashboard)/time-entries/batch-entry-dialog.tsx` — 批量填报组件

**Props**：`open`, `onOpenChange`, `projects`, `onSubmitted`, `existingDailyTotal?`

**State**：
```ts
{ work_date, coordination_matters, tomorrow_plan, rows: [{ project_id, hours, completed_work, remarks }] }
```

**UI 布局**（`sm:max-w-2xl max-h-[85vh] overflow-y-auto`）：
- 顶部：共享工作日期 Input
- 中间：动态行列表，每行 = Card 容器内含 [项目Select + 工时Input] / [完成工作Textarea] / [删除按钮]
- "添加一行"按钮（Plus 图标）
- 底部：共享协调事宜（可选）、明日计划（必填）
- DialogFooter：取消 + 提交

**前端校验**：必填 / hours 范围 / 项目去重 / 总和+existing≤8 / tomorrow_plan 非空

**提交成功后**：
```ts
toast.success(`成功填报 ${result.data.length} 条工时`);
if (result.is_below_minimum) {
  toast.warning(`今日已填报 ${result.daily_total} 小时，不足 8 小时，请确认是否需要补填`);
}
```

#### 5. 修改 `src/app/(dashboard)/time-entries/page.tsx`

- 新增 `showBatch` state 和 `existingDailyTotal` state
- 在"填报工时"按钮旁新增"批量填报"按钮（`Layers` 图标，`variant="outline"`）
- 打开批量 Dialog 前查询当日已有工时，传给子组件
- `handleSubmit`：`apiFetch` 泛型改为含 `daily_total`/`is_below_minimum`，成功后若不足 8h 则 `toast.warning`
- `handleEdit`：同上处理
- 挂载 `<BatchEntryDialog>` 组件

### 三、日总提醒集成

| 场景 | 触发方式 | 提示类型 |
|------|---------|---------|
| 单条新增 | POST 返回 `is_below_minimum` | `toast.warning` |
| 单条编辑 | PUT 返回 `is_below_minimum` | `toast.warning` |
| 批量填报 | batch POST 返回 `is_below_minimum` | `toast.warning` |

提醒为**非阻塞**，不阻止关闭 Dialog 和刷新列表。

## 验证方式

1. 启动开发服务器 `npx tsx src/server.ts`
2. 单条填报 < 8h → 应出现黄色 warning toast
3. 单条填报 = 8h → 仅 success toast，无 warning
4. 批量填报多项目 → 一次提交成功，列表刷新
5. 批量填报重复项目 → 前端/后端拦截报错
6. 批量填报总和 > 8h → 拦截报错
7. 编辑工时后 → 同样根据日总触发提醒
